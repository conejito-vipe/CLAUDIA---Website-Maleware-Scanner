# CLAUDIA 2.20.0 - External mode: check from the outside only, without server access (all seven systems)

- **External mode**: The start page has "External mode: check from outside only (no server access)". Only the address of the website is needed. CLAUDIA detects the system itself (Joomla, WordPress, Drupal, TYPO3, Contao, PrestaShop, Shopware) and shows only the checks that are possible from outside: 10 to 11 per system (page source, security headers, CSP, cookies, TLS, blocklist, threat situation, open interfaces and files of the system, plus the three new checks below). The report notes the external mode. Why: Anyone without SSH (customer site, third-party site, first contact) used to get only a small selection and had to know which. Now the address is enough, and it is clear what was checked and what cannot be checked without server access.
- **New check: system and version from outside (all systems)**: ext_fingerprint detects the system from generator tag, folders, headers, cookies and login pages and reads the version where visible: WordPress (generator, feed, readme.html), Joomla (manifest, language file), Drupal (CHANGELOG.txt, otherwise only the major version), TYPO3 (login page), Shopware (/api/_info/version). For Contao and PrestaShop the version cannot be read reliably from outside; the report says so openly. The version is rated online (WordPress stable-check, Joomla update list, Drupal releases, Packagist advisories for TYPO3, Contao, PrestaShop, Shopware). Why: The version decides whether known vulnerabilities are open. What is readable from outside is also visible to an attacker.
- **New check: visible extensions (all systems)**: ext_components reads from the page source which plugins, themes, modules, components, extensions or packages are included. WordPress: version via readme.txt and comparison with api.wordpress.org (outdated plugins are reported). PrestaShop: version via config.xml of the modules. Core packages (e.g. Contao core, Shopware storefront) are not listed. Why: Extensions are the most common way in; their names are readable by any visitor.
- **New check: forgotten and sensitive files (all systems)**: ext_files requests typical locations: .env, .git, configuration backups (wp-config.php.bak, configuration.php.bak, settings.php.bak, LocalConfiguration.php.bak and others), database dumps, ZIP backups, logs, installation folders, directory listings, the private JWT key for Shopware. Each system adds its own paths (over 70 in total). Why: Forgotten backups often contain credentials and are searched for automatically every day.
- **Switch file: activation without a new release (preparation)**: CLAUDIA can accept a signed switch file (SW1) that controls activation and blocks. It is pasted into the input field of the "License" window and read at start. Checking, connecting, help, updates and the way back always stay free. No public key is entered yet: until then every switch file is discarded and nothing changes. Why: Settings can be changed later without every user installing a new program.
- **Internal**: New file claudia/checks/extern.py, tests/test_extern.py (35 tests); the set EXTERN_IDS in registry.py marks the existing external checks. Why: One list in one place instead of markers in 14 files.

# CLAUDIA 2.20.0 - Externer Modus: Prüfung nur von außen, ohne Serverzugang (alle sieben Systeme)

- **Externer Modus**: Auf der Startseite gibt es "Externer Modus: nur von außen prüfen (ohne Serverzugang)". Nötig ist nur die Adresse der Webseite. CLAUDIA erkennt das System selbst (Joomla, WordPress, Drupal, TYPO3, Contao, PrestaShop, Shopware) und zeigt nur die Prüfungen, die von außen möglich sind: 10 bis 11 je System (Quelltext, Sicherheits-Header, CSP, Cookies, TLS, Sperrliste, Bedrohungslage, offene Schnittstellen und Dateien des Systems plus die drei neuen Prüfungen unten). Der Bericht vermerkt den externen Modus. Warum: Wer kein SSH hat (Kundenseite, fremde Seite, Erstkontakt) bekam bisher nur eine kleine Auswahl und musste wissen, welche. Jetzt reicht die Adresse, und es ist klar, was geprüft wurde und was ohne Serverzugang nicht geprüft werden kann.
- **Neue Prüfung: System und Version von außen (alle Systeme)**: ext_fingerprint erkennt das System an Generator-Angabe, Ordnern, Kopfzeilen, Cookies und Anmeldeseiten und liest die Version, wo sie sichtbar ist: WordPress (Generator, Feed, readme.html), Joomla (Manifest, Sprachdatei), Drupal (CHANGELOG.txt, sonst nur die Hauptversion), TYPO3 (Anmeldeseite), Shopware (/api/_info/version). Bei Contao und PrestaShop ist die Version von außen nicht verlässlich lesbar; das steht offen im Bericht. Die Version wird online bewertet (WordPress stable-check, Joomla-Updateliste, Drupal-Releases, Packagist-Meldungen für TYPO3, Contao, PrestaShop, Shopware). Warum: Die Version entscheidet, ob bekannte Lücken offen sind. Was von außen lesbar ist, sieht auch ein Angreifer.
- **Neue Prüfung: sichtbare Erweiterungen (alle Systeme)**: ext_components liest aus dem Quelltext, welche Plugins, Themes, Module, Komponenten, Erweiterungen oder Pakete eingebunden sind. WordPress: Version über readme.txt und Vergleich mit api.wordpress.org (veraltete Plugins werden gemeldet). PrestaShop: Version über config.xml der Module. Kernpakete (z. B. Contao-Kern, Shopware-Storefront) werden nicht aufgelistet. Warum: Erweiterungen sind der häufigste Einstieg; ihre Namen sind für jeden Besucher lesbar.
- **Neue Prüfung: vergessene und sensible Dateien (alle Systeme)**: ext_files ruft typische Fundorte ab: .env, .git, Konfigurations-Sicherungen (wp-config.php.bak, configuration.php.bak, settings.php.bak, LocalConfiguration.php.bak u. a.), Datenbank-Dumps, ZIP-Sicherungen, Protokolle, Installationsordner, Verzeichnislisten, den privaten JWT-Schlüssel bei Shopware. Je System kommen eigene Pfade dazu (insgesamt über 70). Warum: Vergessene Sicherungen enthalten oft Zugangsdaten und werden täglich automatisch gesucht.
- **Schaltdatei: Freischaltung ohne neues Release (Vorbereitung)**: CLAUDIA kann eine signierte Schaltdatei (SW1) annehmen, die Freischaltung und Sperren steuert. Sie wird im Fenster "Lizenz" in das Eingabefeld eingefügt und beim Start gelesen. Prüfung, Verbindung, Hilfe, Updates und der Rückweg bleiben immer frei. Es ist noch kein öffentlicher Schlüssel eingetragen: bis dahin wird jede Schaltdatei verworfen und es ändert sich nichts. Warum: Einstellungen lassen sich später ändern, ohne dass alle Nutzer ein neues Programm einspielen müssen.
- **Intern**: Neue Datei claudia/checks/extern.py, tests/test_extern.py (35 Tests); die Menge EXTERN_IDS in registry.py markiert die schon vorhandenen externen Prüfungen. Warum: Eine Liste an einer Stelle statt Markierungen in 14 Dateien.

# CLAUDIA 3.1.2 - White window at start, cancel and disconnect, external requests, setup alignment

- **White window at start**: The window icon is now set by pywebview itself on the window thread. If the start still hangs, CLAUDIA writes the position of every program part to the log after 25 seconds and additionally opens the interface in the default browser after 40 seconds. Why: After the first start the window stayed white and Windows reported "not responding". The icon was set directly on the window from a background thread; window and program could block each other.
- **Cancel and disconnect**: Cancel releases the check after at most four seconds, even while a test is waiting for an answer; a new run is possible immediately. Disconnect ends a running check and really closes the connection. Why: After cancelling, "A check is already running" appeared, and after disconnecting the old connection stayed open in the background.
- **External requests (homepage and standard addresses)**: If the homepage cannot be reached from this PC, the external tests are skipped immediately with a reason. Otherwise the progress shows each address, the time limits are shorter, and after three failed attempts or 45 seconds the rest is left out. Slowly trickling answers also end at the deadline. Why: "From outside: detect system and version" stood still for more than three minutes (twelve addresses one after another up to the time limit) and hardly reacted to cancel.
- **Small things**: Version lines (e.g. "Joomla 6.2.1") count as explanation, not as a notice. Between the presets and "Save logs to your PC" there is the same gap as between the other tiles. In the setup, subtitle and content start aligned with the heading on every page. Why: Feedback after testing 3.1.1.

# CLAUDIA 3.1.2 - Weißes Fenster beim Start, Abbrechen und Trennen, Abruf von außen, Setup bündig

- **Weißes Fenster beim Start**: Das Fenstersymbol setzt jetzt pywebview selbst im Fenster-Thread. Hängt der Start trotzdem, schreibt CLAUDIA nach 25 Sekunden die Stelle jedes Programmteils ins Protokoll und öffnet die Oberfläche nach 40 Sekunden zusätzlich im Standardbrowser. Warum: Nach dem ersten Start blieb das Fenster weiß und Windows meldete "reagiert nicht". Das Symbol wurde aus einem Hintergrund-Thread direkt am Fenster gesetzt; dabei konnten sich Fenster und Programm gegenseitig blockieren.
- **Abbrechen und Trennen**: Abbrechen gibt die Prüfung nach spätestens vier Sekunden frei, auch wenn ein Test gerade auf eine Antwort wartet; ein neuer Lauf ist sofort möglich. Trennen beendet eine laufende Prüfung und schließt die Verbindung wirklich. Warum: Nach dem Abbrechen hieß es "Es läuft bereits eine Prüfung", und nach dem Trennen blieb die alte Verbindung im Hintergrund bestehen.
- **Abruf von außen (Startseite und Standardadressen)**: Ist die Startseite von diesem PC aus nicht erreichbar, werden die externen Tests sofort mit Begründung übersprungen. Sonst zeigt der Fortschritt jede Adresse, die Zeitgrenzen sind kürzer, und nach drei Fehlversuchen oder 45 Sekunden wird der Rest ausgelassen. Auch langsam tröpfelnde Antworten enden spätestens zur Frist. Warum: "Von außen: System und Version erkennen" stand über drei Minuten still (zwölf Adressen nacheinander bis zur Zeitgrenze) und reagierte kaum auf Abbrechen.
- **Kleinigkeiten**: Versionsangaben (z. B. "Joomla 6.2.1") gelten als Erläuterung, nicht als Hinweis. Zwischen den Voreinstellungen und "Protokolle auf deinen PC sichern" steht derselbe Abstand wie zwischen den anderen Kacheln. Im Setup beginnen Unterzeile und Inhalt auf jeder Seite bündig mit der Überschrift. Warum: Rückmeldungen nach dem Test von 3.1.1.

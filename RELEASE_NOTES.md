# CLAUDIA 2.19.0 - Automatic updates: now also for Drupal, TYPO3, Contao, PrestaShop, Shopware and WooCommerce

- **Check: Do automatic updates really run? (all systems)**: The check now exists for all seven systems. Drupal: whether 'Update Manager' and 'Automatic Updates' are enabled, when cron last ran and when updates were last looked for, whether the site is managed with Composer. TYPO3: scheduler tasks, overdue tasks, last run. Contao: cron schedule (tl_cron_job), Contao Manager in the web folder. PrestaShop: the modules '1-Click Upgrade' (autoupgrade) and 'Cronjobs', their version and last run. Shopware: scheduled tasks (overdue, failed), auto_update settings, Composer. WooCommerce (on WordPress): Action Scheduler, i.e. overdue and failed tasks. Each system shows its own texts; it is stated explicitly when a system does not install core updates by itself (except Drupal with the 'Automatic Updates' module). Why: A stalled schedule is the most common reason update notices, cleanup and background tasks stop without anyone noticing. Whether a system updates itself is not the rule for these systems; the check says so openly instead of suggesting a safety that is not there.
- **Internal**: New file claudia/checks/auto_updates_cms.py and tests/test_auto_updates_cms.py; CheckDef knows "texts" (own texts per system). Why: One check with the same ID can show suitable descriptions per system without four copies.

# CLAUDIA 2.19.0 - Automatische Updates: jetzt auch für Drupal, TYPO3, Contao, PrestaShop, Shopware und WooCommerce

- **Prüfung: Laufen die automatischen Updates wirklich? (alle Systeme)**: Die Prüfung gibt es jetzt für alle sieben Systeme. Drupal: ob 'Update Manager' und 'Automatic Updates' eingeschaltet sind, wann Cron zuletzt lief und wann zuletzt nach Updates gesucht wurde, ob die Seite über Composer verwaltet wird. TYPO3: Scheduler-Aufgaben, überfällige Aufgaben, letzter Lauf. Contao: Cron-Zeitplan (tl_cron_job), Contao Manager im Webordner. PrestaShop: Module '1-Click-Upgrade' (autoupgrade) und 'Cronjobs', deren Version und letzter Lauf. Shopware: geplante Aufgaben (überfällig, fehlgeschlagen), Einstellungen zu auto_update, Composer. WooCommerce (bei WordPress): Action Scheduler, also überfällige und fehlgeschlagene Aufgaben. Jedes System zeigt eigene Texte; ausdrücklich gesagt wird, wenn ein System Kern-Updates nicht selbst einspielt (außer Drupal mit dem Modul 'Automatic Updates'). Warum: Ein stillstehender Zeitplan ist die häufigste Ursache dafür, dass Update-Hinweise, Aufräumen und Hintergrundaufgaben ausbleiben, ohne dass es jemand merkt. Ob ein System sich selbst aktualisiert, ist bei diesen Systemen nicht die Regel; die Prüfung sagt das offen, statt eine Sicherheit vorzutäuschen.
- **Intern**: Neue Datei claudia/checks/auto_updates_cms.py und tests/test_auto_updates_cms.py; CheckDef kennt "texts" (eigene Texte je System). Warum: Eine Prüfung mit gleicher Kennung kann je System passende Beschreibungen zeigen, ohne vier Kopien.

# CLAUDIA 3.1.1 - JCE update, start problem, fewer false alarms for extensions, interface and setup

- **JCE and other extension updates**: "Update extensions" now loads the package onto the server itself (https only, also across redirects), checks that it is a ZIP, compares the vendor checksum and then installs from the file. If the download server returns a notice page instead of the package, it retries with a browser identification and writes the page title to the log. Why: JCE 3.0.6 failed four times with "Unable to install extension". For the address index.php?...&file=pkg_jce_306.zip Joomla had only loaded an 11.7 KB page.
- **Program log and start**: The Windows and Mac program file writes a log (Windows: %APPDATA%\CLAUDIA\protokoll\claudia.log), including crashes. If the window stays white after the start, CLAUDIA reloads the page once after 15 seconds. After closing, the process ends reliably. The support package contains the last lines of the log. Why: After closing with the X, the window stayed white at the next start, and there was no log for troubleshooting.
- **Installation check in the program file**: The message "PRUEFSUMMEN.txt is missing" no longer appears in the Windows/Mac program file. Why: There all program parts are inside the program file itself; there is no file list.
- **Extensions against the vendor package: fewer false alarms, code window**: Only the files listed in the manifest are compared (the admin folder belongs in administrator/). Package collections with an embedded ZIP and ZIPs with a top folder are opened. Files of a shared library that are identical to the file from another package (e.g. osmylicensesmanager from Joomlashack) and files that differ only in line endings count as fine. Real differences show a code window with the comparison. Joomla's own extensions and package collections are no longer listed as "not checkable"; update addresses without https are tried via https. Why: The report listed 11 changed, 48 additional and 301 missing files, most of which came from the wrong mapping.
- **Threat situation**: Add-on plugins of other extensions (e.g. the ConvertForms plugin for AcyMailing) are no longer confused with the product. If a report names the fixed version and the installed one is newer, the notice is dropped. Why: The ConvertForms plugin "acymailing" was reported as AcyMailing with a critical vulnerability.
- **Results: "fine" means fine**: A check that only contains explanations and a "fine" is shown as "Fine" instead of "Notice". Why: A notice at the top while everything was fine in the details was contradictory.
- **Temp folders**: "Empty temp folder" shows the number of files and the size per folder. Why: So you can decide whether emptying is worthwhile.
- **Interface**: Uninstall is a trash can at the bottom of the sidebar. The navigation icons keep their shape (SVG instead of characters that Windows showed as coloured emojis). The steps can be clicked again from the dashboard and the help. The "Start check" bar and the footer no longer cover the scroll bar. The window buttons show a colour on hover. Notice boxes (e.g. update search) are readable in the dark design. The icons in the dashboard have normal size. The radar shows only the levels found, in their colour, critical findings close to the centre but never in it. Why: Feedback after testing 3.1.0.
- **Setup**: The picture of the Windows message is smaller and fully visible, the text is aligned with the heading, the small logo at the top right is transparent, and the logo on the last page is centred. Why: Feedback after testing 3.1.0.

# CLAUDIA 3.1.1 - JCE-Update, Startproblem, weniger Fehlalarme bei Erweiterungen, Oberfläche und Setup

- **JCE und andere Erweiterungs-Updates**: "Erweiterungen aktualisieren" lädt das Paket jetzt selbst auf den Server (nur https, auch bei Umleitungen), prüft, dass es ein ZIP ist, vergleicht die Prüfsumme des Herstellers und installiert dann aus der Datei. Liefert der Download-Server eine Hinweisseite statt des Pakets, wird es mit Browser-Kennung wiederholt und der Seitentitel ins Protokoll geschrieben. Warum: JCE 3.0.6 scheiterte viermal mit "Unable to install extension". Joomla hatte bei der Adresse index.php?...&file=pkg_jce_306.zip nur eine 11,7 KB kleine Seite geladen.
- **Programmprotokoll und Start**: Die Windows- und Mac-Programmdatei schreibt ein Protokoll (Windows: %APPDATA%\CLAUDIA\protokoll\claudia.log), auch Abstürze. Bleibt das Fenster nach dem Start weiß, lädt CLAUDIA die Seite nach 15 Sekunden einmal neu. Nach dem Schließen endet der Prozess sicher. Das Support-Paket enthält die letzten Zeilen des Protokolls. Warum: Nach dem Schließen über das X blieb beim nächsten Start das Fenster weiß, und es gab kein Protokoll zur Fehlersuche.
- **Installationsprüfung in der Programmdatei**: Die Meldung "PRUEFSUMMEN.txt fehlt" erscheint in der Windows-/Mac-Programmdatei nicht mehr. Warum: Dort stecken alle Programmteile in der Programmdatei selbst; eine Dateiliste gibt es nicht.
- **Erweiterungen gegen das Paket des Herstellers: weniger Fehlalarme, Codefenster**: Verglichen werden nur die Dateien, die das Manifest aufzählt (der admin-Ordner gehört nach administrator/). Paket-Sammlungen mit eingebettetem ZIP und ZIPs mit Oberordner werden geöffnet. Dateien einer gemeinsamen Bibliothek, die identisch mit der Datei aus einem anderen Paket sind (z. B. osmylicensesmanager von Joomlashack), und Dateien, die sich nur in Zeilenenden unterscheiden, gelten als in Ordnung. Echte Abweichungen zeigen ein Codefenster mit der Gegenüberstellung. Joomla-eigene Erweiterungen und Paket-Sammlungen stehen nicht mehr unter "nicht prüfbar"; Update-Adressen ohne https werden per https versucht. Warum: Der Bericht meldete 11 geänderte, 48 zusätzliche und 301 fehlende Dateien, die größtenteils aus der falschen Zuordnung stammten.
- **Bedrohungslage**: Zusatz-Plugins anderer Erweiterungen (z. B. das ConvertForms-Plugin für AcyMailing) werden nicht mehr mit dem Produkt verwechselt. Nennt eine Meldung die behobene Version und ist die installierte schon neuer, entfällt der Hinweis. Warum: Das ConvertForms-Plugin "acymailing" wurde als AcyMailing mit kritischer Lücke gemeldet.
- **Ergebnisse: "in Ordnung" ist in Ordnung**: Eine Prüfung, die nur Erläuterungen und ein "in Ordnung" enthält, steht als "In Ordnung" statt als "Hinweis". Warum: Hinweis oben, im Detail aber alles in Ordnung war widersprüchlich.
- **Temp-Ordner**: "Temp-Ordner leeren" zeigt Anzahl der Dateien und Größe je Ordner. Warum: Damit man entscheiden kann, ob sich das Leeren lohnt.
- **Oberfläche**: Deinstallieren ist ein Papierkorb unten in der Seitenleiste. Die Symbole der Navigation behalten ihre Form (SVG statt Zeichen, die Windows als bunte Emojis zeigte). Aus Dashboard und Hilfe sind die Schritte wieder anklickbar. Die Leiste "Prüfung starten" und die Fußleiste verdecken die Bildlaufleiste nicht mehr. Die Fensterknöpfe zeigen beim Darüberfahren eine Farbe. Hinweis-Kästen (z. B. Update-Suche) sind im dunklen Design lesbar. Die Symbole im Dashboard sind normal groß. Der Radar zeigt nur gefundene Stufen in ihrer Farbe, kritische Funde nah an der Mitte, aber nie ganz darin. Warum: Rückmeldungen nach dem Test von 3.1.0.
- **Setup**: Das Bild der Windows-Meldung ist kleiner und vollständig sichtbar, der Text steht bündig zur Überschrift, das kleine Logo oben rechts ist transparent, auf der letzten Seite steht das Logo mittig. Warum: Rückmeldungen nach dem Test von 3.1.0.
